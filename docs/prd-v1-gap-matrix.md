# PRD v1 实施差距矩阵

本文件以《Academia University 产品需求文档》为产品基线。它记录每个公开版本改善的用户结果、保留范围、明确不做的内容和可执行验收路径。

## v1.0：定位与入口

### 改善的用户结果

用户不需要先写一个完美提示词，也不需要先选择专业，就能：

1. 从六个创造阶段找到最接近当前处境的问题；
2. 看到初步结论、预计时间、现实产物、能力与调用学科；
3. 分辨“旗舰路径编制中”和“问题索引”，不会把未完成内容误认为正式课程；
4. 从问题进入学院或课程，也能从学院、课程返回相关现实问题。

### 保留

- 现有学院、专业、课程和培养方案；
- 现有注册、登录、会话、长期记忆、成绩和项目数据；
- 学院地图及所有旧链接；
- Cloudflare/D1 预览与阿里云正式生产边界；
- 现有管理后台。

### 修改

- 首页从大学宣言和课程规模，转向年轻创造者、真实问题、产物和证据；
- 新增答案地图、30 个核心问题和六条旗舰路径预览；
- 增加内容状态体系：正式开放、研修路径、知识节点、共建中；
- 登录后侧栏增加答案地图，“实践项目”改为“我的课题”，通用 Agent 降低导航优先级；
- 学院与课程页加入相关现实问题的反向入口；
- 新增带路径版本、内容版本和评价版本的答案地图与路径查看事件。

### 明确不做

- 不开放尚未完成的答案路径；
- 不用聊天轮数、阅读或点击声明路径完成；
- 不把 4,192 个课程结构和知识节点宣称为正式开放课程；
- 不扩大院系、专业和课程名称；
- 不按学分收费；
- 不改写或删除现有用户数据；
- 不在 v1.0 实现路径报名、证据提交、Agent 评价和结果回访，这些属于 v1.1。

### 数据兼容

v1.0 使用版本化内容模型和现有通用分析事件表，不需要数据库迁移。新增事件数据写入现有 `analytics_events.properties_json`，不会改变既有业务记录。

### 验收路径

1. `/`：首屏无聊天框，主按钮进入答案地图，学院地图入口明确；
2. `/answers`：六个阶段各五个问题，共 30 个；卡片展示结论、产物、时间、学科和真实状态；
3. `/answers/is-this-a-false-demand`：展示初步结论、误区、用户行动、证据、方法边界、学科关系和版本；
4. `/courses/4p-stp`：能够反向看到相关现实问题；
5. `/college` 与相关学院页：能够进入答案地图或关联问题；
6. 桌面与 390px 手机无横向溢出，主要链接可由键盘访问。

## v1.1：第一条结果闭环

### 改善的用户结果

用户可以在“如何判断一个想法是不是伪需求”中：

1. 以一个真实项目完成基线诊断，而不是先接受一段通用知识；
2. 逐条提交带对象、来源和发生时间的现实证据；
3. 区分访谈、已发生行为、真实成本与反例；
4. 形成版本化需求证据表，明确用户与 Agent 各自完成的部分；
5. 由 Kimi 经统一 `acad-pro` 路由执行反方审阅，并由服务端量规决定是否必须修订；
6. 审阅不通过时提交新版本，不覆盖历史产物；
7. 审阅通过后记录继续、缩小、改变或停止所产生的现实结果；
8. 把路径、证据、产物、评价、结果与能力证据永久写入 D1，并进入长期记忆。

### 完成规则

- 不按页面停留、阅读量或对话轮数完成；
- 第一版产物至少需要三条现实证据才能提交；
- 正式通过要求五位不同对象、真实成本、反例、可追溯来源和完整判断边界；
- 服务端结构量规是状态机的唯一通过依据，模型不能自行把未达标材料标记完成；
- 只有最新产物审阅通过后才能记录现实结果；
- 现实结果写入后，路径才标记为完成并生成能力证据。

### 数据与兼容

- 新增路径报名、基线、证据、产物版本、量规评价、现实结果和能力证据表；
- 所有记录有 UUID、时间戳、软删除字段及路径／内容／评价版本；
- D1/Drizzle 与 PostgreSQL/Prisma 模型保持语义一致；
- 页面和接口继续经 `AcademiaRepository` 访问业务数据；
- 现有用户、学院、课程、会话、订单、记忆、成绩和后台数据未删除或改写；
- 后台“学院与专业”新增答案路径漏斗与证据／修订／结果质量指标。

### 验收路径

1. `/answers/is-this-a-false-demand`：登录前显示学籍门槛，登录后可启动路径；
2. 基线诊断：必填项目、对象、已有依据、最大未知和当前把握；
3. 现实证据：提交后刷新页面仍存在，来源和类型可见；
4. 需求证据表：区分用户与 Agent 贡献，修订会新增版本；
5. Agent 审阅：真实调用 Kimi；材料不足时要求修订，达标后开放结果回访；
6. 现实结果：只有审阅通过才能提交，完成后显示结果状态并写入能力证据；
7. `/admin/academics`：查看路径开始、基线、证据、产物、审阅、修订和结果漏斗；
8. 桌面与 390px 手机无横向滚动，表单、按钮和结果卡均可使用。

## v1.2：六条正式路径与能力档案

### 改善的用户结果

1. 六条旗舰路径全部开放，每条都有独立的行动要求、证据类型、最低数量、作品模板、量规版本和能力映射；
2. 登录后的“我的下一步”优先恢复最近未完成的正式路径，而不是只罗列历史课程；
3. 没有进行中路径时，系统按尚未形成现实证据的能力推荐下一条路径；
4. 新增能力档案，以现实证据、作品版本、量规评价、修订和结果为来源，不以自我评价或 GPA 替代能力；
5. 路径完成后生成独立能力证据，能够回到具体作品、审阅和现实结果；
6. 六条路径继续共用同一套账户、权限、D1 持久化、状态机、模型网关和成本控制。

### 六条正式路径

- 如何判断一个想法是不是伪需求；
- 如何进行不诱导答案的用户访谈；
- 如何把一门课程变成可展示的作品；
- 第一个原型应该做到什么程度；
- 为什么用户说喜欢，却不愿意付出成本；
- 应该继续、调整还是停止一个项目。

每条路径都由七个状态构成：基线、行动、证据、作品、审阅、修订、现实结果。作品通过服务端版本量规后，才能提交现实结果并完成路径。

### 数据与兼容

- 沿用 v1.1 的通用路径表，不新增数据库迁移；
- `answer_path_enrollments.path_slug` 区分六条路径，作品类型、路径版本、量规版本和能力 ID 均由版本化路径配置决定；
- 旧的伪需求路径记录保持可读；新报名写入 v1.2 路径版本，不覆盖旧作品与评价；
- 新增 `/api/me/capabilities` 聚合接口和 `/capabilities` 能力档案页；
- `/api/me/dashboard` 增加可执行的 `nextAction`，课程与成绩数据继续保留；
- `next_path_started`、证据、作品、审阅、修订、结果和能力更新继续进入现有结果漏斗。

### 验收路径

1. `/answers`：六条旗舰路径均显示“已开放”；
2. 任意旗舰路径：可以开始、保存独立基线，并只接受该路径定义的证据类型；
3. 作品表单：标题、模板、最低证据和审阅语境随路径变化；
4. `/home`：首个大卡片展示当前唯一“下一步”，进行中路径优先；
5. `/capabilities`：展示六项能力、层级、证据数、作品、修订、量规和最近来源；
6. 完成一条路径后，能力档案与下一路径推荐同步更新；
7. 桌面与 390px 手机无横向滚动，关键入口可由键盘访问。

## v1.3：知识、成果与专业能力互认

### 改善的用户结果

1. 六条正式答案路径连接到专业能力、课程和可解释的知识节点，用户能双向理解“解决一个问题”与“修读一个专业”之间的关系；
2. 只有路径完成、最新作品通过量规审阅且记录现实结果后，才会成为课程实践学分的候选成果；
3. 学习者主动选择把一份成果用于哪门正式开放课程，同一份成果不能在多门课程中重复抵扣；
4. 每门课程至少保留 1 学分核心理解与期末检验，路径成果不能自动替代完整课程或 GPA；
5. 专业页展示可由哪些现实成果证明具体能力，并同时说明不能被单一成果替代的理论、差异内容和考试；
6. 能力档案可将审阅通过的作品生成公开证明链接，也可随时撤回；
7. 公开证明只呈现作品、用户与 Agent 贡献边界、审阅结果和可选现实结果，不公开邮箱、账户或原始证据来源。

### 数据与兼容

- 新增 `result_recognitions`，记录用户、路径报名、作品、课程、专业、能力、认定学分和知识关系图版本；
- 新增 `artifact_shares`，记录公开短链、标题、摘要、发布和撤回状态；
- 迁移只新增表和索引，不覆盖现有用户、课程、路径、作品、评价、订单或成绩；
- D1/Drizzle 与 PostgreSQL/Prisma 保持同名、同义模型；
- 课程报价按课程互认与现实成果互认后的净学分计算，但课程完成仍需通过剩余学习和期末考试；
- 校务后台新增成果互认数、认定学分和当前公开证明数，数据字典写明口径与限制。

### 验收路径

1. `/answers/is-this-a-false-demand`：可看到关联专业、正式课程、知识节点和可认定实践学分；
2. `/knowledge/behavior-versus-attitude`：可看到定义、边界以及相关路径与课程；
3. `/programs/marketing`：可看到专业能力与真实成果的映射；
4. `/courses/4p-stp`：登录后核验已完成路径，合格成果可主动写入实践学分；
5. `/capabilities`：审阅通过的作品可生成、复制和撤回公开证明；
6. `/proof/:shareSlug`：未登录也能验证公开作品，撤回后链接失效；
7. `/admin/academics` 与 `/admin/definitions`：查看互认、公开证明及其准确口径；
8. 桌面与 390px 手机无横向溢出，互认与分享动作可由键盘完成。
