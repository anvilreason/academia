# PRD v1 实施差距矩阵

本文件以《Academia University 产品需求文档》为产品基线。它记录每个公开版本改善的用户结果、保留范围、明确不做的内容和可执行验收路径。

## v1.0：定位与入口

### 改善的用户结果

用户不需要先写一个完美提示词，也不需要先选择专业，就能：

1. 从六个创造阶段找到最接近当前处境的问题；
2. 看到初步结论、预计时间、现实产物、能力与调用学科；
3. 分辨“旗舰路径编制中”和“问题索引”，不会把未完成内容误认为正式课程；
4. 从问题进入学院或课程，也能从学院、课程返回相关现实问题。

### 保留

- 现有学院、专业、课程和培养方案；
- 现有注册、登录、会话、长期记忆、成绩和项目数据；
- 学院地图及所有旧链接；
- Cloudflare/D1 预览与阿里云正式生产边界；
- 现有管理后台。

### 修改

- 首页从大学宣言和课程规模，转向年轻创造者、真实问题、产物和证据；
- 新增答案地图、30 个核心问题和六条旗舰路径预览；
- 增加内容状态体系：正式开放、研修路径、知识节点、共建中；
- 登录后侧栏增加答案地图，“实践项目”改为“我的课题”，通用 Agent 降低导航优先级；
- 学院与课程页加入相关现实问题的反向入口；
- 新增带路径版本、内容版本和评价版本的答案地图与路径查看事件。

### 明确不做

- 不开放尚未完成的答案路径；
- 不用聊天轮数、阅读或点击声明路径完成；
- 不把 4,192 个课程结构和知识节点宣称为正式开放课程；
- 不扩大院系、专业和课程名称；
- 不按学分收费；
- 不改写或删除现有用户数据；
- 不在 v1.0 实现路径报名、证据提交、Agent 评价和结果回访，这些属于 v1.1。

### 数据兼容

v1.0 使用版本化内容模型和现有通用分析事件表，不需要数据库迁移。新增事件数据写入现有 `analytics_events.properties_json`，不会改变既有业务记录。

### 验收路径

1. `/`：首屏无聊天框，主按钮进入答案地图，学院地图入口明确；
2. `/answers`：六个阶段各五个问题，共 30 个；卡片展示结论、产物、时间、学科和真实状态；
3. `/answers/is-this-a-false-demand`：展示初步结论、误区、用户行动、证据、方法边界、学科关系和版本；
4. `/courses/4p-stp`：能够反向看到相关现实问题；
5. `/college` 与相关学院页：能够进入答案地图或关联问题；
6. 桌面与 390px 手机无横向溢出，主要链接可由键盘访问。
